# tpt-visual

**A memory-safe, GPU-accelerated video processing engine. Real-time compositing, color science, and effects. The brain of the TPT AV visual stack.**

**License:** MIT  
**Status:** Early-stage / Pre-1.0  
**Ecosystem:** [TPT Solutions Open Source](https://opensource.tptsolutions.co.nz/)

---

## 1. Vision & Philosophy

`tpt-visual` is the **video processing layer** of the TPT AV Stack. It provides the foundational crates required to build non-destructive video editors, motion graphics tools, live streaming applications, and visual effects pipelines.

The Rust graphics ecosystem has excellent primitives (`wgpu` for GPU abstraction, `image` for basic manipulation) but **no unified framework** for professional video processing. There is no standard way to represent a non-destructive video edit, no GPU-accelerated compositor that reads from a timeline, and no pure-Rust color science engine that handles HDR, wide gamut, and broadcast standards.

`tpt-visual` fills that gap. It is the "glue" that turns raw video frames from `tpt-kinetix` into a professional, non-destructive video application.

### Core Tenets

1. **Strictly Non-Destructive:** The original video files on disk are never mutated. The engine only manages metadata, edit decisions, and real-time GPU-based transformations.
2. **GPU-Accelerated:** All compositing, color transforms, and effects run on the GPU via `wgpu` (WebGPU) for maximum performance and cross-platform compatibility.
3. **Real-Time Safe:** The rendering pipeline is designed for 60fps+ playback of 4K/8K video with multiple effects layers.
4. **Professional Color Science:** Full support for broadcast standards (Rec.709, Rec.2020, DCI-P3), HDR (HDR10, HLG, Dolby Vision metadata), and industry workflows (ACES, OCIO compatibility).
5. **Clean Thread Boundaries:** Strict separation between the Main/UI Thread (can allocate, can block) and the Render Thread (GPU command submission, minimal CPU overhead).
6. **Pure MIT Licensing:** No GPL/LGPL/MPL dependencies. Enforced via `cargo-deny` in CI.
7. **Composable Architecture:** Each sub-crate is independently useful. A developer can use just the timeline, just the compositor, or just the color engine.

## 2. Ecosystem Integration

`tpt-visual` sits in the **Processing Layer** of the TPT AV Stack, consuming decoded video frames from `tpt-kinetix` and outputting to the display or encoder.

| Crate | Role | Relationship to `tpt-visual` |
| :--- | :--- | :--- |
| **`tpt-kinetix`** | Media containers, video codecs | Decodes video files into raw frames (YUV/RGB). `tpt-visual` consumes these frames. |
| **`tpt-visual`** | **Video processing (this repo)** | Manages the non-destructive timeline, composites video on the GPU, applies color grading and effects. |
| **`tpt-audio`** | Audio processing | Provides synchronized audio playback. `tpt-visual` syncs video frames to the audio timeline. |

### Data Flow

tpt-kinetix (decodes video files → raw frames YUV/RGB)
↓
tpt-av-visual-timeline (manages non-destructive edit state)
↓
tpt-av-visual-compositor (GPU-based rendering, applies effects)
↓
tpt-av-visual-color (color space conversion, HDR tone mapping)
↓
Display / Encoder (outputs to screen or file)

4. Core API Design
4.1. The Timeline Model (tpt-av-visual-timeline)
The timeline is the pure data model of a non-destructive video edit. It does not process video; it only describes what video should be displayed, when, and how.

/// A complete video editing session.
pub struct Session {
    /// Unique session identifier.
    pub id: SessionId,
    /// Session name (e.g., "My Documentary").
    pub name: String,
    /// Frame rate for the entire session (e.g., 24, 30, 60).
    pub frame_rate: FrameRate,
    /// Resolution for the entire session (e.g., 1920x1080, 3840x2160).
    pub resolution: Resolution,
    /// All tracks in the session (ordered by z-index).
    pub tracks: Vec<Track>,
    /// Global metadata (timecode start, color space, etc.).
    pub metadata: SessionMetadata,
}

/// A single video track containing multiple clips.
pub struct Track {
    /// Unique track identifier.
    pub id: TrackId,
    /// Track name (e.g., "Video 1", "Title Graphics").
    pub name: String,
    /// All clips on this track, sorted by start time.
    pub clips: Vec<Clip>,
    /// Track-level opacity (0.0 = transparent, 1.0 = opaque).
    pub opacity: f32,
    /// Track-level blend mode.
    pub blend_mode: BlendMode,
    /// Whether the track is hidden.
    pub hidden: bool,
    /// Whether the track is locked.
    pub locked: bool,
}

/// A non-destructive reference to a video asset.
pub struct Clip {
    /// Unique clip identifier.
    pub id: ClipId,
    /// Reference to the source video asset.
    pub asset_id: AssetId,
    /// Start time of the clip on the timeline (in frames).
    pub start_frame: u64,
    /// Offset into the source asset (in frames).
    /// Allows trimming the beginning of the asset.
    pub source_offset: u64,
    /// Duration of the clip (in frames).
    pub duration_frames: u64,
    /// Spatial transform (position, scale, rotation).
    pub transform: Transform,
    /// Opacity (0.0 to 1.0).
    pub opacity: f32,
    /// Blend mode.
    pub blend_mode: BlendMode,
    /// Keyframe animations (optional).
    pub keyframes: Vec<KeyframeTrack>,
    /// Applied effects (optional).
    pub effects: Vec<EffectInstance>,
}

/// A reference to a video file on disk.
pub struct VideoAsset {
    /// Unique asset identifier.
    pub id: AssetId,
    /// File path to the source video file.
    pub file_path: PathBuf,
    /// Duration of the asset (in frames).
    pub duration_frames: u64,
    /// Frame rate of the asset.
    pub frame_rate: FrameRate,
    /// Resolution of the asset.
    pub resolution: Resolution,
    /// Pixel format of the asset (e.g., YUV420, RGB).
    pub pixel_format: PixelFormat,
    /// Color space of the asset (e.g., Rec.709, Rec.2020).
    pub color_space: ColorSpace,
}

/// Spatial transform for a clip.
pub struct Transform {
    /// Position (x, y) in pixels.
    pub position: (f32, f32),
    /// Scale factor (1.0 = 100%).
    pub scale: (f32, f32),
    /// Rotation in degrees.
    pub rotation: f32,
    /// Anchor point (rotation center) as normalized coordinates (0.0 to 1.0).
    pub anchor: (f32, f32),
}

/// A keyframe animation track.
pub struct KeyframeTrack {
    /// Property being animated (e.g., "transform.position.x").
    pub property: String,
    /// Keyframe points (time, value).
    pub keyframes: Vec<Keyframe>,
    /// Interpolation method (linear, cubic, bezier).
    pub interpolation: InterpolationMethod,
}

/// A single keyframe point.
pub struct Keyframe {
    /// Time position (in frames).
    pub frame: u64,
    /// Value at this point.
    pub value: f32,
    /// Bezier control points (for cubic interpolation).
    pub bezier: Option<(f32, f32, f32, f32)>,
}

5.3. Shader Pipeline
All effects and compositing operations use WGSL (WebGPU Shading Language):

// Example: Gaussian blur shader (blur.wgsl)

@group(0) @binding(0) var input_texture: texture_2d<f32>;
@group(0) @binding(1) var input_sampler: sampler;
@group(0) @binding(2) var<uniform> blur_params: BlurParams;

struct BlurParams {
    direction: vec2<f32>,  // (1,0) for horizontal, (0,1) for vertical
    radius: f32,
}

struct VertexOutput {
    @builtin(position) position: vec4<f32>,
    @location(0) tex_coords: vec2<f32>,
}

@vertex
fn vs_main(@builtin(vertex_index) vertex_index: u32) -> VertexOutput {
    // Full-screen triangle
    var positions = array<vec2<f32>, 3>(
        vec2<f32>(-1.0, -1.0),
        vec2<f32>( 3.0, -1.0),
        vec2<f32>(-1.0,  3.0)
    );
    
    var output: VertexOutput;
    output.position = vec4<f32>(positions[vertex_index], 0.0, 1.0);
    output.tex_coords = (positions[vertex_index] + 1.0) * 0.5;
    return output;
}

@fragment
fn fs_main(input: VertexOutput) -> @location(0) vec4<f32> {
    var color = vec4<f32>(0.0);
    var total_weight = 0.0;
    
    // Gaussian blur kernel
    for (var i = -4; i <= 4; i++) {
        let offset = vec2<f32>(f32(i)) * blur_params.direction;
        let weight = exp(-0.5 * f32(i * i) / (blur_params.radius * blur_params.radius));
        color += textureSample(input_texture, input_sampler, input.tex_coords + offset) * weight;
        total_weight += weight;
    }
    
    return color / total_weight;
}

6.2. Render Thread vs. UI Thread

Main/UI Thread (Can Allocate, Can Block)
│
│  Mutate timeline state
│  Load/unload video assets
│  Update UI
│  Trigger frame prefetching
│
Render Thread (Minimal CPU, GPU-Bound)
│
│  Read timeline state (lock-free snapshot)
│  Build compositing graph
│  Submit GPU commands
│  Present frames to display
